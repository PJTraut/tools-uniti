# UNITI v0.001a5 History and Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add reversible edit transactions and an incremental recovery journal without document snapshots.

**Architecture:** `EditHistory` stores `EditTransaction` objects containing character-based replace operations (`start`, deleted text, inserted text) and a cursor/saved cursor. `Document` routes mutations through one replace primitive, so undo/redo replay bypasses history recording but still invalidates logical line state. Recovery uses append-only JSON Lines with source identity and edit operations; replay reconstructs the edited state from the immutable source plus deltas.

**Tech Stack:** Python 3.12+, dataclasses, JSON Lines, pytest.

**Spec:** `docs/superpowers/specs/2026-08-31-uniti-v0.001-alpha-completion-design.md`

## Global Constraints

- No full document snapshots for undo or recovery.
- History is user state, not disposable cache.
- Unicode character offsets remain authoritative for edits.
- Recovery journal records source identity and edit deltas only.
- Version after milestone: `v0.001a5` / `0.1a5`.
