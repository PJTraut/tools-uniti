# UNITI v0.001a10 Reliability and Alpha Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the private `v0.001a*` series as a recoverable, externally-safe, launchable desktop alpha with a reproducible headless smoke workflow and packaging suitable for runtime testing on macOS/Windows/Linux.

**Architecture:** External file identity is tracked in the Qt-independent `Document` and checked before overwriting the current logical path. Recovery is coordinated by a Qt-independent app service that lazily journals edits and clears journals after successful saves/clean closes; the Qt shell only presents recovery choices. Settings paths, JSON settings, and diagnostics are app services with no Qt dependency, while packaging keeps PySide6 optional so the core remains testable headlessly.

**Tech Stack:** Python 3.12+, `regex==2026.5.9`, optional PySide6>=6.8, pytest, stdlib JSON/path/platform APIs.

**Spec:** `docs/superpowers/specs/2026-08-31-uniti-v0.001-alpha-completion-design.md`

## Global Constraints

- Qt never becomes the document store and `uniti.core` remains Qt-free.
- Existing source bytes remain immutable/addressable; normal save preserves untouched invalid bytes.
- Saving to the current logical path must refuse an external identity mismatch before any write starts.
- Recovery journals contain deltas, not source-file copies, and are removed after successful save or clean close.
- Startup recovery must validate source identity before replay.
- Settings and diagnostics must import and work without PySide6.
- The command-line launcher must fail clearly when PySide6 is absent.
- Version after milestone: `v0.001a10` / `0.1a10`.
