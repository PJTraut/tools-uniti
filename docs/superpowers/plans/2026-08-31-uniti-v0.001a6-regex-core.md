# UNITI v0.001a6 Regex Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pinned third-party `regex` package the bounded search/replace engine for the virtual document.

**Architecture:** Search consumes bounded logical text windows with `partial=True`, retaining only unresolved suffix context for ordinary patterns and conservatively retaining prefix context for explicit lookbehind/absolute-anchor patterns. Engine `Match` objects are transient; public results store only absolute 64-bit spans/capture spans. Ordinary Replace All collects compact results and applies one transaction; streaming rewrite yields unchanged/replacement text chunks directly to the atomic text writer.

**Tech Stack:** Python 3.12+, `regex==2026.5.9`, existing Document/PieceTable/save pipeline, pytest.

**Spec:** `docs/superpowers/specs/2026-08-31-uniti-v0.001-alpha-completion-design.md`

## Global Constraints

- Python `regex`, never `re`, executes user patterns.
- Search is cancellable and each engine call has timeout support.
- Zero-width patterns must progress safely.
- Public result count must not imply GUI object count.
- Cross-window matches must work through partial-match extension.
- Version after milestone: `v0.001a6` / `0.1a6`.

---

### Task 1: Document iteration and result types
Create `Document.iter_text`, `CaptureRecord`, and `MatchRecord`; test bounded progressive iteration and repeated/named capture metadata.

### Task 2: Regex compiler and streaming search
Create compiler/search modules; test invalid patterns, normal/cross-window/zero-width/named/repeated captures, cancellation, timeout, and bounded early result delivery.

### Task 3: Transactional Replace All
Add `Document.replace_many` and regex replacement collection using transient `Match.expand`; test length-changing replacements and one-step undo/redo.

### Task 4: Streaming rewrite
Add atomic encoded text-chunk writer and regex `stream_replace_to_file`; test large match counts, EOL/encoding policy, and no document mutation.

### Task 5: Version and acceptance
Advance to a6 and run regex acceptance across a >10 MB document plus full verification.
