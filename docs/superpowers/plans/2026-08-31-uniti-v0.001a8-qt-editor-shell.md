# UNITI v0.001a8 Virtual Qt Editor Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the first launchable PySide6 UNITI desktop shell while keeping the custom document engine authoritative.

**Architecture:** Editing semantics live in a Qt-independent `EditorState` controller over `Document`. `UNITITextView(QAbstractScrollArea)` asks `Document` for only visible lines, paints them with `QPainter/QTextLayout`, and translates input events into `EditorState` commands; it never stores the document in `QTextDocument`, `QPlainTextEdit`, or another Qt text model. `MainWindow` owns tabs/documents and normal File/Edit actions. PySide6 stays an optional dependency and imports only below `uniti.ui` or the launcher.

**Tech Stack:** Python 3.12+, optional PySide6>=6.8, existing UNITI core/resources, pytest; Qt runtime tests skip when PySide6 is unavailable.

**Spec:** `docs/superpowers/specs/2026-08-31-uniti-v0.001-alpha-completion-design.md`

## Global Constraints

- Qt never becomes the document store.
- `uniti.core`, `uniti.regex`, and `uniti.resources` remain PySide6/PyQt-free.
- Initial rendering is no-wrap, monospaced, viewport-only.
- Opening a file must not call `Document.line_count()` or `Document.total_chars()` merely to show the first viewport.
- Scroll range may grow progressively; explicit End can force full line indexing.
- Version after milestone: `v0.001a8` / `0.1a8`.
