# UNITI v0.001a9 Regex / Encoding / EOL UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the a8 desktop shell into a practical text editor with syntax-aware regex Find/Replace, capture inspection, visible match overlays, explicit output encoding/EOL policy, source EOL analysis, reinterpretation, and character inspection.

**Architecture:** Regex syntax tokenization and result indexing stay Qt-independent in `uniti.regex`. UI search executes on the a7 worker pool while the target view is temporarily mutation-disabled; results remain compact records and only viewport intersections are painted. Encoding conversion is represented as document output metadata and applied by the existing streaming save path. Source EOL analysis opens an independent byte source in a worker so closing/editing the active document cannot race the analysis.

**Tech Stack:** Python 3.12+, `regex==2026.5.9`, optional PySide6>=6.8, UNITI resources/core, pytest.

**Spec:** `docs/superpowers/specs/2026-08-31-uniti-v0.001-alpha-completion-design.md`

## Global Constraints

- Python `regex` remains the sole execution engine.
- Regex highlighter is lexical only; it never executes patterns itself.
- GUI result count does not imply one GUI object per match.
- Long search/replace collection runs off the Qt UI thread and is cancellable.
- Text mutation is disabled on a view while its worker search/replace reads that document.
- Reinterpretation is same bytes/different decoder and is refused while unsaved edits exist.
- Conversion/EOL changes are explicit output policy and make the document logically modified until saved.
- Version after milestone: `v0.001a9` / `0.1a9`.
