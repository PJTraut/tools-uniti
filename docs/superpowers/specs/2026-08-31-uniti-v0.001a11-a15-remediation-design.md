# UNITI v0.001a11-a15 Remediation Design

## Goal

Apply every release-blocking and material alpha-usability recommendation from the `v0.001a10` full code review without changing UNITI's frozen Architecture v0.1 ownership model.

## Scope and milestone sequence

### v0.001a11 — Data-integrity hardening

Separate source-decoding metadata from output-conversion metadata in recovery. Preserve matching BOM metadata when an explicit decoder is selected. Preserve POSIX file mode across atomic replacement and define best-effort metadata copying for timestamps/xattrs where supported without making unsupported metadata fatal. Fix Save-As/Reinterpret semantics to use the current logical path. Correct the repository test command/import layout.

### v0.001a12 — Editing and huge-line performance

Coalesce sequential edit-store runs so normal typing does not create one permanent piece/block per character. Keep the public PieceTable API stable while allowing its internal representation to evolve. Remove whole-line materialization from End/vertical movement, add bounded line-window navigation, horizontal viewport windowing, and make Select All a logical range that may use lazy EOF discovery rather than building the whole text. Add performance regression gates for sequential typing and giant lines.

### v0.001a13 — Search scalability

Replace UI-facing all-results tuples with a bounded paged/spooled `MatchStore`. Keep only core offsets eagerly and resolve captures/text for the current/visible result on demand. Bind search state to `Document.revision` and invalidate on mutation. Route large Replace All automatically to the streaming rewrite path. Patterns requiring unbounded retained prefix must either use an explicit bounded fallback or be rejected for whole-document virtual search with a clear error rather than silently retaining the full prefix.

### v0.001a14 — Resource integration

Introduce one application `ResourceManager` that owns cache budgets, pressure state, and the shared priority worker scheduler. Register document mapper/index/search caches with priorities; support pressure-driven reclamation and active/inactive tab priority changes. Replace per-panel worker pools with the shared scheduler. Move recovery fsync off the synchronous typing path using a journal worker with bounded durability interval and explicit flush on save/close.

### v0.001a15 — Desktop alpha hardening

Make inserted newline policy distinct from output conversion policy: homogeneous source uses its EOL, mixed source uses dominant EOL, new documents use configured default, explicit policy overrides. Add Cut/Copy/Paste and IME composition support. Surface invalid-byte spans distinctly in viewport/character inspection. Reconcile regex capture numbering with engine semantics for advanced constructs. Run every available Qt test; package a Mac runtime-test candidate. PySide6/macOS manual verification remains an external environment gate if the sandbox cannot provide Qt.

## Architectural invariants preserved

1. Qt never becomes the authoritative document store.
2. `uniti.core` remains PySide6-free.
3. Source bytes remain immutable/addressable while their file identity is valid.
4. Opening never requires decoding the whole file.
5. Ordinary save is byte-preserving where safe; conversion is explicit.
6. Reinterpretation never silently becomes conversion.
7. CR/LF/CRLF remain explicit document metadata and editing policy.
8. Third-party `regex` remains authoritative for regex semantics.
9. No long document operation runs synchronously on the UI thread.
10. Result count must not dictate GUI object count or unbounded RAM use.
11. Cache ownership and reclamation are centralized.
12. User edits/history are not disposable cache.
13. Save remains streaming and atomic/crash-conscious.
14. No deliberate 1 GiB ceiling is introduced.

## Compatibility policy

The `v0.001a10` public core interfaces remain source-compatible unless a review finding requires an additional field/method. Internal data structures may change. Recovery journal format is versioned; readers accept the alpha10 format only when it can be interpreted safely, otherwise they fail closed with a clear recovery error.

## Verification gates

Every milestone requires:

- red-green tests for every corrected defect;
- the full non-Qt suite;
- `compileall` and `git diff --check`;
- confirmation that `src/uniti/core` and `src/uniti/regex` do not import PySide6;
- targeted performance gates for any performance remediation;
- optional Qt runtime tests whenever PySide6 is present.

`v0.001a15` is not merged/tagged automatically. It remains on the development branch until the user chooses integration after Mac runtime validation.
