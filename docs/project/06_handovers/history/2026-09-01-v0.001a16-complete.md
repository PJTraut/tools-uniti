## Verification incident and correction

An early real-bootstrap verification exposed that `DependencyManager` resolved the managed Python symlink to its base executable. That run invoked pip through the base interpreter and left the venv's old `0.1a15` distribution metadata in place. The root cause was fixed by preserving the absolute managed symlink path. Bootstrap and normal/self-check validation now reject installed UNITI metadata that differs from canonical package metadata, and a real symlink regression prevents recurrence.

After correction, `.venv` reports both imported and installed UNITI as `0.1a16`, and deep self-check passes. The base Python currently reports an editable `uniti-editor 0.1a16`; it was not removed because its prior ownership/state was unknown.
