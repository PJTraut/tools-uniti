# UNITI v0.001 Alpha Completion Design

## Goal

Complete the `v0.001a*` series as the first usable private UNITI desktop alpha while preserving Architecture v0.1 invariants: UNITI owns the text, Qt never becomes the document store, file operations remain progressive/streaming, encoding and EOL state remain explicit, and the third-party `regex` package is authoritative.

## Alpha exit criterion

The alpha is complete when a user can launch UNITI, open a text file without whole-file decode, navigate and edit it through UNITI's virtual document model, undo/redo, search/replace with Python `regex`, inspect/change encoding and EOL policy, save safely through a streaming writer, recover from an unsaved-edit journal, and use a minimal cross-platform Qt Widgets shell. Large-file architecture must remain valid at and beyond the 1 GiB design target.

## Milestones

### v0.001a3 — Edited-document navigation

Add a piece-aware logical line index using Unicode character offsets. Provide `line_count`, `line_start`, `line_for_char`, `read_line`, and `read_lines`. Index progressively and invalidate from the first affected logical line after edits. Preserve CR/LF/CRLF semantics across piece boundaries.

### v0.001a4 — Streaming save and conversion

Add a piece iterator and streaming document writer. Untouched source pieces may be copied directly only when output encoding and EOL policy are unchanged and byte preservation is safe. Otherwise stream logical Unicode through explicit EOL conversion and target encoding. Save via same-directory temporary file, fsync, and atomic replace. Reject unrepresentable output instead of silently replacing characters.

### v0.001a5 — Undo/redo and recovery primitives

Represent edits as reversible operations/transactions. Support undo/redo for insert/delete/replace without document snapshots. Add an incremental recovery journal containing original path/identity, logical edit operations, cursor-neutral document metadata, and a clean-close marker. Recovery must not duplicate the source file.

### v0.001a6 — Regex search/replace core

Use only the pinned third-party `regex` engine. Add compiled-pattern validation, bounded-window document scanning, compact match records, capture offsets, cancellation/timeout controls, zero-width progress protection, and replacement expansion. Whole-document replace must support a streaming rewrite path for large transformations.

### v0.001a7 — Resource and worker services

Add Qt-independent memory budgeting, cache priority/eviction primitives, memory-pressure states, cancellation tokens, and bounded worker scheduling. The UI thread contract is represented as a priority model; actual Qt signal integration follows in a8. `psutil` is optional at runtime with a conservative fallback.

### v0.001a8 — Virtual Qt editor shell

Add optional PySide6 UI package and entry point. `UNITITextView(QAbstractScrollArea)` renders only requested logical lines through `Document`; it must not use `QPlainTextEdit`/`QTextDocument` as document storage. Add main window, tabs, menus, status bar, cursor/selection basics, scrolling, and keyboard insertion/deletion. Core imports remain Qt-free.

### v0.001a9 — Regex / encoding / EOL UI

Add Find/Replace controls, regex syntax tokenization/highlighting, visible-match overlays, capture-group inspector, encoding/EOL status controls, conversion/reinterpret commands, and character inspection. Result storage remains independent from GUI object count.

### v0.001a10 — Reliability and alpha packaging

Add external-file identity checks, recovery startup flow, settings paths, diagnostics snapshot, application launcher, packaging metadata, and smoke tests. Validate the headless core on generated large files and validate Qt imports/runtime when PySide6 is available. `v0.001a10` is the alpha-exit candidate; no Git tag is created until the user chooses to integrate/tag it.

## Public core boundaries

`uniti.core` remains Qt-independent. New public responsibilities are separated into focused modules:

- `document_lines.py` — logical edited-document lines
- `save.py` — save policy and streaming document writer
- `history.py` — undo/redo transactions
- `recovery.py` — recovery journal format
- `regex/*` — regex execution/search/results/replace
- `resources/*` — memory/cache/work scheduling
- `ui/*` — PySide6-only presentation and interaction

## Error handling

Invalid source bytes remain explicit decode-error characters and are byte-preservable when untouched and saved without conversion. Encoding conversion must fail with structured unrepresentable-character information. Save commits only after successful write/flush/fsync. Regex work is bounded and cancellable. UI failures in optional decoration/search overlays must not corrupt the document.

## Testing strategy

Every production behavior follows red-green TDD. Core tests run without PySide6. Qt tests are marked optional and skipped when PySide6 is unavailable. Acceptance tests cover CR/LF/CRLF across piece boundaries, multibyte encodings, invalid bytes, >1 GiB sparse sources, zero-width regex, large result counts without GUI objects, streaming save, recovery replay, and headless package imports.

## Explicitly deferred beyond this alpha

Full document syntax highlighting, project/workspace concepts, LSP, plugins, Git integration, terminal, AI features, cloud/account features, hex editing, sophisticated accessibility bridge, and polished platform installers are not alpha-exit requirements.
