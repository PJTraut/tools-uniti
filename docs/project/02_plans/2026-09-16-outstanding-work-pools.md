## Why this document exists

The feedback log accumulates one `BF-NNN` entry per item, in report order. That's the right structure for disposition history, but it doesn't answer "what's left, and how does it cluster for planning the next pass of work" — this document is that view, refreshed periodically rather than maintained line-by-line. It does not replace the feedback log or the [ROADMAP](ROADMAP.md)'s milestone-level sequencing; it sits between them, at the level of "which outstanding `BF-NNN` items make sense to batch together next."

## Pool 0 — 2026-09-21 feedback batch

Seven items from a batch of external beta-tester feedback ([BF-076](../BETA_FEEDBACK.md#bf-076--character-inspector-refresh-button-for-newly-selected-text)–[BF-082](../BETA_FEEDBACK.md#bf-082--file-tabs-stack-files-per-group-longer-filenames-paging-nav)), reviewed against the current codebase before logging (not just transcribed) — see each entry for the exact existing-code citation — plus two more (BF-083, BF-084) found live during the same triage session, not from the original batch. None needed new architecture except BF-081/082, flagged below.

**Landed 2026-09-21** (see each entry in the [Beta Feedback Log](../BETA_FEEDBACK.md) for implementation and verification):

- [BF-076](../BETA_FEEDBACK.md#bf-076--character-inspector-refresh-button-for-newly-selected-text) — Character Inspector refresh on new selection: a Refresh button/hotkey rebuilds content in place via a new `refresh()` method, reusing BF-073's toggle-window mechanism.
- [BF-079](../BETA_FEEDBACK.md#bf-079--match-report-capture-group-labelscontent-render-in-a-proportional-font-not-monospaced) — Match Report capture-group font is now the resolved editor monospace font, primary rather than fallback-only.
- [BF-078](../BETA_FEEDBACK.md#bf-078--compare-highlight-the-selected-line-in-both-panes-with-a-distinct-tint) — Compare cross-pane selected-line now gets a distinct background tint, alpha-blended over any hunk-kind color already on that line, alongside the existing gutter marker bar.
- [BF-080](../BETA_FEEDBACK.md#bf-080--match-report-match-count-status-and-valid-pattern--n-groups-placement) — the match-count status label moved out of the Find row onto a new centered spot on the actions row, staying visible even when the Match Report panel is collapsed — the user's own resolution once a literal move under the Match Report was found to hide busy/error/cancel feedback whenever that panel closes.
- [BF-083](../BETA_FEEDBACK.md#bf-083--findreplace-a-negated-character-class--falsely-forces-full-document-context-retention-discarding-all-matches-on-a-large-document) — not part of the original batch; found live while chasing a "no matches" report during this same session. A negated character class (`[^...]`, an everyday SFM marker-pairing idiom) was mistaken for a `^` line anchor by a naive substring check, forcing the bounded search engine to retain the whole scanned buffer forever instead of trimming it — silently discarding every match already found once a large document crossed the 1 MiB retained-context cap. Long-standing (present since the original bounded-search commit), not a recent regression. Fixed with a character-class-aware scan before the anchor/lookbehind substring checks run.
- [BF-084](../BETA_FEEDBACK.md#bf-084--file-menu-no-close-all-command) — also not part of the original batch; found live in the same session. `close_all_documents()` already existed (used internally for app-quit) and was already safe (per-document unsaved-changes prompting) but had no menu entry; wired to a new **File → Close All**.
- [BF-077](../BETA_FEEDBACK.md#bf-077--compare-enable-line-wrap) — Compare line wrap. Resolves BF-070's 2026-09-18 finding: the user chose the full wrap-aware scroll-sync rework (2026-09-22) over the accept-imprecision fallback — new `UNITITextView.visual_row_for_line`/`line_for_visual_row` convert between a logical line and each pane's own scrollbar value (line index, or wrapped-row index when wrap is on), so `uniti.core.text_diff`'s alignment math stays wrap-agnostic. Per-pane toggle in Compare's right-click context menu.
- [BF-081](../BETA_FEEDBACK.md#bf-081--groups-save-group-close-group) — Groups: save group, close group. **New architecture**, landed 2026-09-22: `DocumentGroup` gained a `saved_paths` field (persisted, membership-only, no order/position); Save/Close/Open Saved actions added to the tab's group context menu, Close prompting per-document exactly like `close_all_documents` (BF-084).

**Still open:**

- [BF-082](../BETA_FEEDBACK.md#bf-082--file-tabs-stack-files-per-group-longer-filenames-paging-nav) — File tabs: per-group stacking, horizontal groups/vertical files, paging nav. **New architecture, in progress.** Scoped with the user 2026-09-21: per-split stacking — each `PaneLeaf` gets its own horizontal group row/vertical file stack, layered onto the existing `EditorPaneTree` split model, not a window-wide concept spanning splits. Interaction model refined 2026-09-22 and built as an interactive HTML prototype for the user (and a tester) to try before real code — the actual `panes.py`/`_DetachableTabBar` rework is blocked on that feedback. The Recent-Files sub-piece (longer list, remembers/restores a file's group) has already landed independently.

- [BF-085](../BETA_FEEDBACK.md#bf-085--match-report-shrink-capture-group-label-text-10-leave-rowcell-size-unchanged) — Match Report capture-group label text now renders at 90% of the content font size; the reserved label column and row height are untouched.
- [BF-086](../BETA_FEEDBACK.md#bf-086--findreplace-highlight-the-erroring-regex-span-with-a-background-tint-not-just-a-text-message) — the erroring regex span now gets a low-alpha background tint (derived from the existing per-theme `_invalid_color`) alongside its existing wavy underline, in both the Find and Replace fields for free (shared highlighter code path).
- [BF-087](../BETA_FEEDBACK.md#bf-087--character-inspector-persist-the-listdetail-splitters-column-width-across-reopens) — the list/detail splitter's position now persists across reopens via a new `Settings.toggle_window_splitter_sizes` dict, mirroring the existing geometry/zoom mechanism exactly.
- [BF-088](../BETA_FEEDBACK.md#bf-088--findreplace-pasting-literal-whitespace-into-a-regex-mode-field-should-convert-to-its-regex-escape) — pasting a literal CR/LF/TAB into the Find or Replace field now converts it to `\r`/`\n`/`\t` while Regex mode is on; literal mode keeps the raw byte.
- [BF-090](../BETA_FEEDBACK.md#bf-090--docked-findreplace-expands-to-fill-the-whole-panel-when-no-document-is-open) — docked Find/Replace with zero documents open now reserves its usual bounded height (a new `EditorPaneTree.split_pane`, splitting the empty root pane directly) instead of filling the whole window; confirmed not Windows-specific despite the report's "(windows)" tag.
- [BF-091](../BETA_FEEDBACK.md#bf-091--match-report-drop-the-colon-from-the-capture-group-label) — the capture-group label dropped its trailing colon (`\1 :` → `\1 `).
- [BF-092](../BETA_FEEDBACK.md#bf-092--match-report-font-size-coupled-to-findreplace-fields-zoom) — the Match Report's font size no longer moves in lockstep with the Find/Replace fields' zoom; each has its own persisted state, and wheel-zoom routes by which widget it lands on. Native macOS confirmation received.
- [BF-093](../BETA_FEEDBACK.md#bf-093--match-report-capture-group-label-truncates-to--at-some-zoom-levels) — found while investigating BF-092: a multi-digit label could truncate to `\1…` at some zoom levels even at its own measured width (a `QFontMetrics.horizontalAdvance`/`elidedText` boundary disagreement); fixed with a small safety margin. Native macOS confirmation received.
- [BF-094](../BETA_FEEDBACK.md#bf-094--windows-native-findreplace-dock-controls-render-but-dont-work) — removed the native Qt dock-widget features (`Closable`/`Floatable`/`Movable`) on the Find/Replace window; provably inert everywhere (never really docked, custom title bar already replaces native drag, no native close button drawn), just visibly broken on Windows specifically. Needs native Windows re-confirmation — reasoned from the code's own architecture, not reproduced first-hand.
- [BF-089](../BETA_FEEDBACK.md#bf-089--unicodechar-function-improvements) — clarified 2026-09-25 as specifically the Word-Alt+X-style hex↔character toggle (BF-053): gave it a default `Ctrl+Alt+X` binding (previously unbound), and raised the minimum recognized hex-run length from 1 to 4 digits, closing a real, previously-accepted ambiguity (a bare trailing letter like `A` used to forward-convert as the control character `0x0A` instead of reversing to `U+0041`).
- [BF-096](../BETA_FEEDBACK.md#bf-096--held-unicode-inspections-single-character-codepoint-peek-is-redundant-with-bf-089s-hex-toggle) — found live while wiring BF-089's new hotkey: the held `Ctrl+Alt`/`Cmd+Option` inspection popup's single-character codepoint+name peek was redundant with BF-089's toggle (and with the Character Inspector, which already covered the same need) — removed just that half; the unrelated whitespace-marker-type reveal the same held combo also drives stays untouched.

Nothing left open in this pool.

BF-070's five 2026-09-18 follow-up findings landed the same day, four of five fully: the "full editor parity" rework (swapping Compare's bespoke `_ComparePlainTextEdit` for real read-only `UNITITextView` panes onto the live documents), the standalone top-level window, zoom sync, cross-pane current-line highlight, and (after a user-reported gap in the initial rework) intra-line/segment-level diff highlighting within a changed line are all implemented.
