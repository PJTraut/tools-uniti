# UNITI v0.001b1 Real-World Feedback Beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote a completely green A24 candidate to `v0.001b1`, qualify private cross-platform beta bundles, and complete a bounded fourteen-day real-world feedback gate with three independent platform testers.

**Architecture:** Preserve A24 as an exact immutable evidence boundary, then create B1 through a separate version/documentation promotion commit on `main`. Extend the A23/A24 private build pipeline with one deterministic top-level tester-information file, and use a separate private developer script to validate content-free feedback evidence; UNITI itself gains no network, telemetry, account, or feedback-upload authority.

**Tech Stack:** Python 3.12+, PySide6/Qt executable bundles inherited from A23, canonical JSON and SHA-256, `pyside6-deploy`/Nuitka build tooling inherited from A23, pytest, CTest, GitHub Actions, and Markdown project records.

**Spec:** [`docs/project/02_plans/v0.001b1-real-world-feedback-beta-design.md`](v0.001b1-real-world-feedback-beta-design.md)

## Global Constraints

- Do not begin Task 2 until every A24 checklist item and required local/hosted/clean-host/bundle gate is `PASS` on one exact candidate; `WARN`, `INVALID`, `NOT RUN`, a skip, or mismatched commit blocks admission.
- Execute on canonical `main`, preserve unrelated user changes, and keep the A24 closure and B1 promotion as separate commits.
- Promotion identity is exactly `v0.001b1` for display and `0.1b1` for PEP 440/package metadata.
- Push the verified B1 candidate to `origin/main`; do not create a Git tag, GitHub release, public package, installer publication, or updater.
- B1 remains feature-frozen. Admit only defect correction, reproduction/diagnostic clarity, tester documentation, bounded feedback evidence, or release-blocking safety/compatibility work.
- Feedback is opt-in and manually submitted. UNITI never uploads telemetry, diagnostics, documents, or feedback automatically.
- Reuse A23 health, diagnostic export, repair, Safe Session, bundle manifest, clean-host, inventory, reproducibility, and privacy authorities; do not create competing application authorities.
- Every B1 bundle contains exactly one top-level UTF-8 `BETA_TESTER_INFO.txt`, listed in its manifest and capped at 64 KiB.
- Repository feedback evidence is capped at 256 KiB and 1,000 aggregate coverage-plus-issue records and contains only the fixed content-free vocabulary in the design.
- Raw comments, support bundles, screenshots, reproduction documents, paths, document/search/replacement content, personal data, and machine identifiers never enter Git or CI artifacts.
- The feedback gate requires fourteen calendar days on the current qualifying behavior candidate and three independent testers, with macOS, Windows, and Linux each represented.
- A critical safety report pauses distribution. A behavior-changing correction requires a new build identity and all-platform requalification; the changes listed in the design restart the fourteen-day clock.
- Low-space and corruption tests use injected facts or disposable owned copies only. Never fill a real filesystem or corrupt an accepted/distributed bundle.
