# UNITI v0.001a23 Executable Health & Recovery Alpha Implementation Plan

Source-version update, 2026-09-08: B2 is active under [ADR-0007](../05_decisions/ADR-0007-beta-source-version-and-qualification.md). This record retains its original milestone identity and outstanding acceptance requirements for release qualification; historical identity-promotion prerequisites no longer hold the source version at A22.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship UNITI as a native GUI application bundle that diagnoses startup read-only, self-heals only safe allowlisted state, guides consent-based repair/recovery, and no longer exposes a supported public CLI.

**Architecture:** Add a Qt-free `uniti.health` package containing strict report, probe, policy, maintenance, quarantine, and repair authorities. A service-owned controller and one Health & Recovery Center consume those authorities; a small C++17 native launcher handles the failure boundary below Python/Qt and starts the standalone `pyside6-deploy`/Nuitka inner application through a private bounded protocol.

**Tech Stack:** Python 3.12+ source compatibility with CPython 3.12.4 embedded in candidate bundles, PySide6 6.11.2/Qt Widgets, `regex==2026.5.9`, Nuitka 4.1.1 through `pyside6-deploy` standalone mode, standard-library JSON/hash/filesystem/IPC primitives, C++17/CMake, AppKit on macOS, Win32 on Windows, POSIX plus D-Bus notification support on Linux, pytest, CTest, and GitHub Actions.

**Spec:** [A23 Executable Health & Recovery Alpha Design](v0.001a23-executable-health-recovery-design.md)

## Global Constraints

- Begin only after A22 is implemented and A23 is the sole active milestone; execute directly on `main` as requested.
- Keep `HealthEngine`, `MaintenanceEngine`, `RepairEngine`, their models, and their tests Qt-free.
- The quick health path warns at 250 ms and fails at 500 ms on the controlled reference host.
- Pre-editor maintenance gets one pass and one recheck inside the same 500 ms aggregate hard deadline; it never loops.
- Automatic maintenance can touch only exact UNITI-owned disposable or unambiguous derived state and cannot reduce document, recovery, session, undo/redo, saved-history, or external-edit evidence.
- Consent-based repair remains separate; new repair actions never inherit automatic authority.
- Shared quarantine is bounded by the first of seven days or 128 MiB and never prunes current rollback state or protected evidence.
- One process-lifetime `UNITIService`, one Health & Recovery Center, and one F/R panel own all windows and native open requests.
- Closing the last editor window leaves the service running; only explicit Quit ends it through the existing Save/Discard/Cancel authority.
- Native activation accepts at most 128 paths; all messages and exported evidence retain fixed byte/count bounds and exact schemas.
- The shipped application is offline and GUI-only: no public CLI, shell repair, network repair, updater, elevation, installer, signing, or notarization.
- Build independently on macOS, Windows, and Linux; the bundle must not use host Python, source checkout state, the working directory, or `PATH` to locate itself.
- Use CPython 3.12.4 for all candidate bundles and record compiler/CMake/platform toolchain identities in normalized build evidence.
- Bundle inventory growth warns at 10% and blocks at 20% pending explicit review.
- Inject LOWDISK/capacity failures. Never fill, reserve, or truncate the real filesystem to synthesize them.
- Corrupt only disposable bundle copies in tests; never alter an accepted or installed bundle.
- Do not push, tag, publish, sign, package for distribution, or create a release without separate authorization.

## File and Responsibility Map

- `src/uniti/health/model.py`: immutable issue/action/report/result vocabulary and safe canonical serialization.
- `src/uniti/health/probes.py`: fixed probe registry, cooperative/daemon deadline runner, quick/deep orchestration.
- `src/uniti/health/state_probes.py`: bounded read-only application-state probes.
- `src/uniti/health/bundle.py`: quick launcher header and full bundle-manifest validation.
- `src/uniti/health/policy.py`: exact issue-to-disposition/action mapping and automatic-eligibility predicate.
- `src/uniti/health/quarantine.py`: same-filesystem reversible storage, retention, rollback, and conflicts.
- `src/uniti/health/ledger.py`: bounded safe automatic-maintenance audit records.
- `src/uniti/health/maintenance.py`: sealed automatic plans and one-pass execution.
- `src/uniti/health/repair.py`: consent tokens, repair plans, verified transactions, and rollback.
- `src/uniti/app/health_startup.py`: startup classification, single maintenance pass, Safe Session route, and pending-open policy.
- `src/uniti/app/health_controller.py`: one service-owned health/UI/task coordinator.
- `src/uniti/app/launcher_protocol.py`: Python side of the private inherited readiness/activation channel.
- `src/uniti/ui/health_center.py`: issue-first accessible model and Health & Recovery window.
- `launcher/`: Qt/Python-independent C++17 launcher core, native adapters, and CTest coverage.
- `deployment/`: pinned deployment spec, locks, inventory policy, icons/metadata, and accepted size anchors.
- `scripts/a23_build.py`, `scripts/a23_ci.py`: private build/verification entry points excluded from bundles.
