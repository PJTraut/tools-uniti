# UNITI v0.001a21 Cross-Platform Alpha Design

Date: 2026-09-05
Status: approved
Milestone: [`v0.001a21` — Cross-Platform Alpha](v0.001a21-cross-platform-alpha.md)

## Goal

Prove one canonical UNITI source architecture on macOS, Windows, and Linux without weakening the text-integrity, resource, regex-intelligence, recovery, or session guarantees implemented through A20.

A21 is source-distribution proof. It validates bootstrap, launchers, the complete test suite, deep self-check, platform paths and capabilities, local instance arbitration, and real Qt platform plugins on hosted runners. It does not build installers or application bundles.

## Approved decisions

1. GitHub-hosted CI is the authoritative three-OS acceptance environment; physical-machine visual checks are supplemental.
2. The lean required matrix is macOS/Python 3.12, Windows/Python 3.12, Linux/Python 3.12, and Linux/newest-stable Python.
3. There is one shared architecture. Platform branches are confined to focused path, durability, launcher, and Qt UI policy seams.
4. Capability detection is truthful. UNITI distinguishes full durability, file-synced durability, and unsafe persistence instead of assuming POSIX directory `fsync` everywhere.
5. Session generation redundancy and bounded scanning remain the fallback when a current pointer cannot be trusted or parent-directory sync is unavailable.
6. Qt standard keys own platform-native shortcut defaults; persisted overrides remain portable strings under stable command IDs.
7. Font selection uses concrete installed fixed-pitch families and validates Latin plus Cyrillic coverage.
8. Hosted performance timings are evidence only, not release thresholds. Controlled performance policy remains local and A22 owns sustained dogfood/performance work.
9. CI produces no distributable packages and uploads bounded diagnostics only.
10. A21 cannot be frozen complete until all four required jobs pass on the same commit. A push needed to obtain that evidence requires separate authorization.

## Existing baseline and gaps

The A20 baseline already provides substantial portability foundations:

- `pathlib.Path` is used throughout the source, bootstrap, session, and recovery paths;
- `AppPaths.for_platform` has macOS, Windows, and XDG layouts;
- runtime Python discovery knows POSIX `bin/python` and Windows `Scripts/python.exe`;
- `uniti.command` safely delegates to the bootstrap shim on POSIX systems;
- `uniti.bat` provides the Windows `cmd.exe` path;
- PySide6 supplies cross-platform Widgets, standard key sequences, `QLockFile`, and `QLocalServer`;
- capability probes already report runtime, filesystem, mmap, Qt, font, clipboard, input-method, screen, and DPI facts;
- document Save stages, verifies, syncs, and atomically replaces output;
- A20 session/recovery code publishes immutable bounded generations and preserves the previous complete generation; and
- tests inject platform names for several bootstrap and path decisions.

The baseline is not yet cross-platform proof. There is no hosted CI workflow. Windows launcher tests are skipped on macOS, Linux is described as a fallback rather than an explicit supported family, XDG values are accepted without rejecting relative paths, durability helpers assume POSIX-shaped directory handles, current session publication treats strict directory sync as universally available, platform shortcut literals remain mixed with Qt standard keys, font selection remains embedded in the editor widget, and no one acceptance record proves the same commit on all target operating systems.

## Scope

A21 includes:

- explicit macOS, Windows, and Linux family classification;
- platform-correct application paths and invalid-environment fallback;
- canonical filesystem/document identity for existing and not-yet-existing paths;
- capability-aware atomic persistence and recovery/session durability reporting;
- recovery of the newest complete generation without relying exclusively on one pointer;
- POSIX and Windows launcher proof with spaces, Unicode, metacharacters, working-directory preservation, overrides, interpreter discovery, and exit propagation;
- Qt-resolved standard shortcut defaults with portable persisted overrides;
- extracted installed-font selection with fixed-pitch and Latin/Cyrillic facts;
- native instance lease/local-socket tests on every target family;
- deterministic offscreen and native-plugin smoke on each target family;
- an exact cross-platform skip policy and bounded machine-readable evidence; and
- a fail-closed GitHub Actions workflow with four required jobs.

## Outside A21

A21 does not add signed or unsigned installers, `.app`, `.dmg`, `.msi`, `.exe`, AppImage, Flatpak, Snap, package-manager manifests, automatic updating, code signing, notarization, sandbox entitlements, file associations, shell integration, desktop entries, or an installed permanent daemon.

A21 does not broaden editor/regex behavior, add project concepts, tune hosted-runner timing thresholds, replace PySide6, vendor Python, bundle fonts, or create separate OS-specific document engines. Accessibility and deeper manual visual certification remain beta/platform-release work unless a functional defect requires correction now.

## Approaches considered

### Selected: capability-driven canonical architecture

Keep semantic code shared and place genuine operating-system differences behind small explicit seams. Real capability probes decide what the current filesystem and Qt platform can guarantee. CI exercises the exact same public bootstrap/application paths used by developers.

This exposes degradation rather than hiding it, minimizes duplicated logic, and preserves one set of A17-A20 correctness contracts.

### Rejected: CI-only patching

Adding a matrix and fixing individual failures in place would be quicker initially. It would also encourage scattered `sys.platform` checks, make durability claims depend on incidental host behavior, and leave the next platform regression without a stable contract.

### Rejected: full per-OS application backends

Separate macOS, Windows, and Linux implementations could isolate platform details strongly. UNITI does not have enough platform-specific behavior to justify three service, persistence, or UI implementations. The duplication would make correctness fixes diverge and increase beta risk.

## Architecture

```text
host OS name + environment
        |
        v
Qt-free platform classification
        |
        +--> AppPaths absolute root policy
        +--> filesystem durability adapter --> capability facts
        +--> bootstrap runtime/launcher policy
        |
        v
QApplication / Qt platform plugin
        |
        +--> standard shortcut policy
        +--> installed fixed-font selection
        +--> local instance transport
        |
        v
unchanged UNITIService / Document / session / recovery semantics
        |
        v
bounded self-check JSON + four-job acceptance evidence
```

`src/uniti/core`, `src/uniti/regex`, and `src/uniti/resources` remain free of UI and platform-family policy. They may use standard portable filesystem primitives already required by their responsibilities, but cannot acquire separate macOS/Windows/Linux semantic implementations.

Focused platform helpers return immutable values and accept platform names, environments, or filesystem adapters explicitly in tests. They do not read global state throughout the application or become a general service locator.

## Supported platform families

The classifier recognizes:

| Family | Runtime names | UI plugin proof |
|---|---|---|
| macOS | `darwin` | Cocoa |
| Windows | names beginning with `win` | Windows |
| Linux | names beginning with `linux` | XCB under Xvfb plus offscreen |

An unknown family produces a clear platform/startup failure. It does not inherit Linux/XDG behavior accidentally. This alpha makes no BSD, WSLg, Cygwin, Wine, Wayland-only, mobile, or WebAssembly support claim.

The platform family is observed, not persisted as document semantics. Saved sessions retain portable paths as strings local to the same application-data identity; A21 does not introduce cross-machine session synchronization.

## Path policy and identity

`AppPaths` remains the single authority for config, data, state, and cache roots.

- macOS uses `~/Library/Application Support/UNITI` for config/data and `~/Library/Caches/UNITI` for cache, with state below Application Support as already implemented.
- Windows uses an absolute nonempty `LOCALAPPDATA` when valid and otherwise falls back below the user's home AppData/Local directory.
- Linux honors only absolute nonempty `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, and `XDG_CACHE_HOME`. A missing, empty, or relative value uses the corresponding specification-style home fallback.

Derived paths never concatenate separators manually. Tests cover home and checkout paths containing spaces, non-ASCII text, dots, shell metacharacters, and long nested components within runner/filesystem limits. Windows tests additionally cover drive-qualified paths, UNC representation, case variants, and separators through `pathlib`/native APIs rather than hand-built path strings.

Existing paths use native file identity when available. For lexical comparison before a path exists, one focused helper resolves without requiring existence and applies native normalization rules. Case folding is never applied to POSIX paths. The document registry, Save As duplicate detection, instance request normalization, session restore, and recovery lookup consume the same comparison rule.

Symlink/junction resolution remains bounded to operating-system APIs. A missing or inaccessible target remains an explicit result; identity code does not invent equivalence.

## Durability capability model

One Qt-free durability component centralizes file flush, atomic replace, and parent-directory publication behavior. Callers receive a result containing the attempted operation, capability level, and safe failure detail.

| Level | Required facts | Product behavior |
|---|---|---|
| `full` | file sync, atomic replacement, and parent-directory sync succeed | Publish normally and report full durability. |
| `file_synced` | file sync and atomic replacement succeed; directory sync is unavailable | Publish immutable session generations, retain the previous complete generation, scan complete generations on restore, and report reduced power-loss durability in diagnostics. |
| `unsafe` | file sync or atomic replacement is unavailable/fails | Refuse the affected new session/history publication, preserve the prior complete generation, mark recovery/session durability degraded, and surface the failure. |

Capability means observed behavior on the active filesystem, not a promise inferred only from the OS name. Tests inject each result and each failure boundary. Real runner probes operate only on bounded UNITI-owned temporary files and never fill disk space.

Document Save remains stage → flush → file sync → reread/verify → identity check → atomic replace. It never falls back to direct overwrite. Parent-directory sync is attempted where supported and its result is observable. A failure before replacement preserves destination bytes; a post-replacement durability downgrade is reported accurately rather than claiming the source was not changed.

Settings and setup state use the same portable primitive but keep their existing malformed/future-schema rules. Recovery journals keep the last durable prefix and enter visible degraded state when file durability fails.

## Session generation discovery

The current pointer remains the fast path, not the only source of truth. Bounded restore inspects at most the existing generation limit, validates names before opening, orders candidates by embedded generation rather than directory enumeration order, and selects the newest complete manifest whose referenced packs all validate.

Pointer outcomes are:

- valid pointer to a complete generation: load it immediately;
- missing, stale, truncated, or invalid pointer: scan bounded generation candidates;
- pointer to an incomplete generation: reject it and continue the bounded scan;
- no complete generation: return explicit empty/problem state without deleting evidence; and
- successful scan recovery: schedule pointer repair through the normal durability adapter after the session becomes usable.

The previous complete generation remains protected until a later complete publication is current. Scanning validates encoded/decoded lengths, checksums, containment, schemas, counts, and pack ownership before allocation exactly as A20 requires.

## Bootstrap and launcher contract

`scripts/bootstrap.py` remains the only compatibility shim and `uniti.bootstrap` remains the managed-runtime owner. Normal application startup never invokes pip or performs repair.

`uniti.command` is documented and tested as the POSIX source launcher for both macOS and Linux. It resolves its own physical directory, preserves the caller's working directory, passes every argument exactly once, honors `UNITI_PYTHON`, discovers supported Python candidates, executes the one bootstrap path, and returns its exit code.

`uniti.bat` provides the equivalent `cmd.exe` contract. Tests use real `cmd.exe` on Windows and include quoted spaces, Unicode, `%`, `&`, parentheses, override paths, discovery ordering, missing Python, and nonzero exit propagation. PowerShell invokes the batch launcher; A21 does not add a competing `.ps1` bootstrap implementation.

CI first exercises the public launcher/bootstrap `--dev --no-launch` path in a clean checkout. Subsequent commands use the resulting owned `.venv`, proving that test success does not depend on an unrelated pre-created environment.

## Shortcut policy

Command IDs, scopes, collision rules, and overrides remain in the Qt-free registry. Default construction moves behind one Qt UI policy that is created only after `QApplication` exists.

Where Qt exposes a `QKeySequence.StandardKey`, that value is authoritative. UNITI-specific commands use one small platform table only when no standard key exists. Portable text is stored; native text is presentation only. An override remains attached to its stable command ID across operating systems and is revalidated against the current platform's scope/collision set during load.

A malformed, unknown, or newly conflicting override is ignored with a bounded settings notice rather than disabling another command. A user-cleared shortcut remains distinct from an absent override/reset-to-default value.

Tests assert semantic commands and modifiers using Qt key combinations, not English glyph rendering. Native display tests confirm Command-oriented notation on macOS and Control-oriented notation on Windows/Linux without hard-coding localized menu strings.

## Font policy

Fixed-pitch font selection moves out of `UNITITextView` into one focused UI helper. It enumerates installed families, applies a short platform-aware preference order, confirms `QFontDatabase.isFixedPitch`, resolves the concrete family with `QFontInfo`, and validates representative Latin `A` and Cyrillic `Ж` glyphs with `QFontMetrics.inFontUcs4`. This avoids the native process termination observed when hosted headless Windows converted a `QFont` through `QRawFont`.

The result records requested family, resolved family, fixed-pitch status, required glyph coverage, and whether fallback occurred. The editor and Qt capability report consume the same result; they cannot disagree about the active family.

If no installed font satisfies the full contract, UNITI uses the system fixed font to stay usable but reports degraded glyph coverage in diagnostics. A21 does not download or bundle fonts. Required CI images must resolve at least one qualifying installed family or the platform job fails.

## Local instance transport

The A20 one-service protocol remains bounded and versioned. A21 runs its real two-process convergence, activation-only, Unicode/spaced file forwarding, malformed-frame, live-owner timeout, stale-owner recovery, and close/reacquire tests on every OS family.

Endpoint names continue to derive from the resolved application-data identity and remain within Qt's platform-safe length. `QLocalServer.UserAccessOption` is requested everywhere. Failure to obtain a safe lease or endpoint never authorizes a second writer.

No TCP fallback is added. Local transport details remain contained in `InstanceService`; the service/document layers consume only validated `InstanceRequest` and `InstanceReply` values.

## Hosted CI architecture

One workflow uses an explicit include matrix rather than a Cartesian product:

| Job identity | Runner family | Python selector |
|---|---|---|
| `macos-py312` | current supported GitHub macOS image | `3.12` |
| `windows-py312` | current supported GitHub Windows image | `3.12` |
| `linux-py312` | current supported GitHub Ubuntu image | `3.12` |
| `linux-latest` | same Ubuntu image | newest stable `3.x` |

Runner image labels and official action revisions are selected and recorded in the implementation plan because those external values change over time. Actions are pinned to immutable commit revisions with readable version comments. Workflow permissions are `contents: read`; no secrets, write permissions, release events, or deployment credentials are used. Required jobs do not use `continue-on-error`, and `fail-fast: false` preserves evidence from every platform when one fails.

Each job performs:

1. checkout and selected Python setup;
2. public launcher/bootstrap creation of the owned source `.venv` with UI/development dependencies and no application launch;
3. package/version/dependency validation inside the managed interpreter;
4. complete pytest with JUnit output;
5. `compileall` for `src`, `scripts`, `benchmarks`, and `tests`;
6. deep self-check with bounded JSON evidence;
7. deterministic Qt offscreen combined smoke;
8. native Qt smoke using Cocoa, Windows, or XCB under Xvfb;
9. exact skip-policy validation; and
10. bounded diagnostic/JUnit upload only when the job fails.

The newest-stable Linux lane is deliberately moving and detects forward incompatibility. The three Python 3.12 lanes prove the declared minimum. A21 does not multiply every Python version across every OS.

## Skip policy and evidence

Platform-inapplicable tests may skip only under an exact checked-in allowlist. Each OS-specific launcher or native contract skipped on one family must execute on its owning family elsewhere in the same required workflow. Capability-dependent xattr or directory-sync outcomes are recorded facts; correctness tests inject both supported and unsupported states so absence does not erase coverage.

A standard-library verifier reads JUnit XML and fails a job for an unknown skip reason, unexpected skip count, or a test that should run on the current family. Static A21 acceptance tests also validate the required workflow identities, Python selectors, commands, permissions, absence of allowed failures, and native/offscreen coverage.

Deep self-check adds one `cross-platform` result containing only bounded non-sensitive facts: family, Python/Qt versions, platform plugin, path-root categories rather than full user paths, filesystem capability statuses, durability level, selected font family/coverage, and launcher/runtime mode. It does not expose document contents, environment variables, usernames, or IPC payloads.

CI logs and failure artifacts are operational evidence, not release packages. A21 closure records the commit and four successful run/job URLs in current Status and Handover.

## Native smoke policy

Offscreen smoke runs on all four jobs and remains the deterministic widget gate. Native smoke additionally uses:

- default Cocoa on macOS;
- default Windows Qt plugin on Windows; and
- XCB within `xvfb-run -a` on Ubuntu.

The existing combined smoke must create a service, open/edit/save one Unicode file, exercise global Find/Replace state/history, close to zero windows while the service remains alive, reactivate/create a window, restore a session/history, and explicitly Quit. A21 adds platform facts, shortcut/font assertions, local instance forwarding, and Unicode/spaced paths without introducing long-lived invisible CI processes.

Physical-machine checks may supplement hosted evidence for visual quality, input methods, DPI, and window-manager behavior. Their absence does not block A21, but any discovered correctness defect does.

## Performance policy

Shared hosted-runner timing and RSS values are too variable to become release thresholds. CI may record bounded durations and memory facts for diagnosis, but it does not run the controlled quick/routine/design-target suite as a timing gate.

The packaged A18-A20 performance policy, deterministic functional scenarios, cancellation contracts, worker-thread rules, and local controlled baselines remain unchanged and mandatory. A22 owns sustained corpus work and threshold changes.

## Failure and security behavior

- A failed matrix job is a failed A21 gate; no required lane is advisory.
- A missing PySide wheel, missing native plugin, unresolved qualifying font, launcher quoting defect, unknown skip, or bootstrap ownership mismatch fails its platform lane.
- A missing optional filesystem feature becomes an explicit capability fact only when the corresponding safe fallback passes.
- A failed atomic replace/file sync never silently publishes new session state or directly overwrites a document.
- A failed directory sync yields `file_synced`, preserves complete generations, and remains visible in diagnostics.
- CI uses no repository write token, secrets, external service credentials, or release upload.
- Diagnostic artifacts are bounded and contain no source-document text, raw environment dump, user home path, recovery payload, or session pack.
- Tests create files only inside pytest/UNITI-owned temporary roots and never consume real disk capacity to simulate low space.

## Implementation sequence

1. Add Qt-free platform classification, absolute environment-root validation, native path comparison, and their pure tests.
2. Centralize durability results and adapt atomic state/session/recovery callers without weakening Save.
3. Make bounded complete-generation discovery repair a missing/stale pointer.
4. Normalize launcher contracts and extend real POSIX/Windows argument tests.
5. Centralize Qt shortcut defaults and migrate portable overrides safely.
6. Extract font resolution and expose one authoritative coverage result.
7. Add cross-platform deep self-check/native smoke evidence and exact skip verification.
8. Add the pinned lean GitHub Actions workflow and A21 acceptance guard.
9. Run local full/inherited gates, obtain separately authorized remote CI evidence, correct platform defects test-first, and freeze A21 only after all four lanes pass on one commit.

Every product change follows RED → GREEN → refactor and receives a focused local `main` commit. Platform fixes must improve the shared seam rather than patch only the CI shell unless the behavior is inherently shell-specific.

## Milestone acceptance

A21 is complete only when:

1. macOS, Windows, and Linux are explicitly classified and unknown systems do not inherit Linux policy;
2. every application/runtime path is absolute, platform-correct, and free of hard-coded user homes, drives, or manual separators in shared code;
3. Unicode/spaced/metacharacter launcher arguments and exit codes survive real POSIX and Windows shells;
4. document identity and duplicate detection behave correctly for native case/path rules without folding POSIX paths;
5. full/file-synced/unsafe durability states are deterministic, visible, and failure-safe;
6. missing/stale/invalid session pointers recover the newest complete bounded generation without deleting evidence;
7. Save retains staged verification and never falls back to direct overwrite;
8. Qt standard shortcut defaults, portable overrides, clearing, reset, collision handling, and native display pass on each family;
9. a concrete installed fixed-pitch font with Latin/Cyrillic coverage is selected and reported on each required runner;
10. local instance arbitration and forwarding converge on one primary on each family;
11. complete pytest, compileall, deep self-check, offscreen smoke, native smoke, and exact skip verification pass in all four required jobs on the same commit;
12. the workflow has read-only permissions, immutable action pins, bounded failure artifacts, no allowed failures, and no packaging step;
13. inherited A17-A20 correctness, recovery/session, resource, regex, cancellation, and no-real-LOWDISK contracts remain green; and
14. no known platform-specific data-loss, direct-overwrite, concurrent-writer, launcher-corruption, path-identity, missing-plugin, shortcut, font-coverage, GUI-freeze, or unbounded-allocation blocker remains.

## Documentation boundary

During implementation, A21 behavior remains planned intent in `02_plans`. Current scope and architecture change only when verified implementation becomes true. The milestone remains active until all four hosted jobs pass on the same commit and the evidence is recorded.

At complete acceptance, the milestone and implementation plan move to `03_implemented/milestones`, this design moves to `03_implemented/designs`, current documentation/version metadata advance to `v0.001a21` / `0.1a21`, A21 leaves the roadmap, and A22 Dogfood / Performance Alpha becomes active.

No package artifact, tag, release, or push is implied. The one push needed to execute authoritative hosted CI remains a separate user-authorized action.
