# UNITI v0.001a22 Dogfood / Performance Alpha Implementation Plan

> **For Codex:** Use `superpowers:test-driven-development` for every feature or defect task, and `superpowers:verification-before-completion` before every completion claim. Execute this plan sequentially on `main`; do not create a worktree, push, tag, package, or release without separate authorization.

**Goal:** Add deterministic sustained workload gates, safe crash/pressure evidence, and a bounded always-on local dogfood recorder, then prove A22 through a lean cross-platform matrix, two controlled fifty-cycle runs, native/sparse evidence, and seven active dogfood days.

**Architecture:** Extend the existing benchmark corpus/runner/policy system with schema-2 sustained records while retaining schema-1 point-baseline compatibility. One child reuses one `UNITIService` per workload family for one warm-up plus five hosted or fifty controlled cycles. Production owns a separate fixed-vocabulary recorder whose aggregates use shared metric names but never import benchmark-control code.

**Tech stack:** Python 3.12+, PySide6/Qt Widgets, `regex==2026.5.9`, standard-library JSON/gzip/hash/subprocess/filesystem primitives, pytest, GitHub Actions, and the existing UNITI resource/session/recovery infrastructure.

**Governing design:** [A22 Dogfood / Performance Alpha Design](v0.001a22-dogfood-performance-design.md)

## Execution rules

- Begin each implementation task with the listed failing test. Confirm the failure is for the intended missing behavior before changing production code.
- Keep every commit limited to the task's named files except for a directly required import/export or fixture adjustment.
- Preserve the existing thirteen point scenarios and schema-1 baselines throughout.
- Use only resolved harness-owned temporary roots for destructive crash/cleanup tests.
- Inject LOWDISK and other pressure states. Never fill, reserve, or truncate the real filesystem to create pressure.
- Treat `FAIL`, `INVALID`, and `NOT RUN` distinctly. Never convert missing or incompatible evidence into a pass.
- Stop and diagnose any unrelated regression before proceeding.
- Keep `main` clean between tasks. Existing A21 closure commits remain untouched.
