# UNITI v0.001a23 — Executable Health & Recovery Alpha

Date: 2026-09-05
Status: queued
Roadmap order: 2
Design: [A23 Executable Health & Recovery Alpha Design](v0.001a23-executable-health-recovery-design.md)
Implementation: [A23 Executable Health & Recovery Alpha Implementation Plan](v0.001a23-executable-health-recovery-implementation.md)

## Goal

Ship UNITI as a native desktop application bundle whose fast read-only startup health check either opens the editor or presents specific, consent-based repair/recovery guidance without relying on a public command-line interface.

## Approved focus

- native macOS, Windows, and Linux application bundles with embedded Python, PySide6, and runtime dependencies;
- a minimal Python/Qt-independent launcher with a bounded readiness handshake and fatal-runtime guidance;
- a typed quick/deep health engine and tiered healthy/warning/blocking/fatal startup outcomes;
- a separate allowlisted maintenance engine for deterministic, bounded self-healing without modal interruption;
- one service-owned Health & Recovery Center that reuses existing recovery authority;
- offline, local-only, previewed repair transactions with seven-day/128 MiB reversible quarantine;
- Safe Session startup that preserves persisted session/recovery evidence;
- native OS file-open/activation forwarding to the one running UNITI service;
- full bundle manifests, bounded inventory/size gates, and clean-host executable proof; and
- retirement of public console commands and shell launchers after executable parity passes.

## Required gate

- healthy bundled startup reaches the editor automatically;
- every unresolved supported problem produces applicable guidance instead of silent termination;
- routine UNITI-owned disposable or unambiguous derived-state faults self-heal automatically, verify once, and remain auditable;
- repairs require consent, preserve user documents/recovery evidence, and verify or roll back;
- Safe Session bypasses damaged application state without deleting it;
- one running service owns every native launch/open request;
- bundles run without host Python or source checkout state;
- macOS, Windows, and Linux executable/corruption-copy tests pass;
- quick health stays within its controlled 250 ms warning/500 ms failure budget;
- normalized bundle inventory growth remains reviewed and bounded; and
- no known startup dead-end, unsafe repair, data-loss, or silent-failure defect remains.

Signing, notarization, polished installers, automatic updating, network repair, and malicious-tamper guarantees remain outside A23.
