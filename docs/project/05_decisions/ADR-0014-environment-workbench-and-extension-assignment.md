# ADR-0014: Environment Workbench — Per-Environment Commands, Menus, Extension Assignment, and Plain Text Fallback

Date: 2026-10-02
Status: accepted (implemented — see the [implementation record](../03_implemented/milestones/2026-10-02-environment-workbench-plan.md))

## Context

ADR-0013 built the environment seam (E1–E6): every document resolves to an environment key, and JSON/XML/YAML/SFM/USFM environments exist with validation and (USFM) chapter/verse indexing. But nothing in the UI consumed any of it — `FileEnvironmentManager.activate_for` was only called from tests, and the editor's file-type features (Format/Minify, Markdown Preview) were still wired straight into `main_window.py`, gated on the per-view *syntax profile* rather than on any environment.

Request (2026-10-02): a full file-type environment that owns its functions, tools, features and menus; the ability to assign file extensions to environments (e.g. `.USFM` + `.sfm` → USFM); and every environment able to fall back to "plain text within the environment".

## Decision

1. **Every syntax profile gets exactly one environment, in one catalog.** `core/environments/catalog.py` lists Plain Text, Markdown, XML, JSON, YAML, SFM, USFM, CSV, TSV, sharing keys with `syntax_profiles.PROFILES` (ADR-0013 decision 3). New: `MarkdownEnvironment`, `CsvEnvironment`/`TsvEnvironment` (column-count validation via the stdlib `csv` module, so quoted fields count correctly). An environment's default rendering profile is its own key's profile, so "which environment" and "which default profile" cannot disagree.
2. **Environments contribute commands as Qt-free data.** `core/environment_commands.py`: an environment's optional `commands()` returns `EnvironmentCommand`s. A *core* command's `run(context, argument)` receives only the restricted `EnvironmentContext` and returns a declarative result (`ReplaceDocumentText`, `ShowFindings`, `NavigateTo`, `ShowMessage`); a *host feature* (Markdown Preview) is declared by id and implemented by the UI. Commands use stable environment-local ids (`format`, `minify`, `validate`, `go_to_verse`, `preview`) so "Format Document" means whichever environment's `format`. ADR-0013 decision 6 holds: environments still never touch Qt, and a command that raises is reported, not propagated.
3. **One top-level menu per environment, titled after the active document's environment.** It sits between View and Tools, and is retitled/rebuilt on every active-view change (e.g. **USFM**: Go to Chapter:Verse…, Validate USFM | Plain Text Mode | File Type Environments…). Contents are flat separated blocks, per the project's menu preference (blocks over submenus). Format/Minify leave the Format menu and Markdown Preview leaves View — they are now environment features. Shortcuts: see decision 9.
4. **Extension assignment is edited per environment, stored in the existing override map.** View > File Type Environments… (replacing BF-063's flat Text-Type Profiles list) shows one row per environment with every extension it owns, defaults included; typing `.USFM, .sfm` on the USFM row assigns both. Extensions are case-insensitive and stored without the dot. Saving stores only the difference from the defaults in the already-persisted `Settings.syntax_extension_overrides` (now read as extension → environment key; values were already profile keys, which are environment keys), so no settings schema change. A default extension removed from its environment and not given to another is stored as an explicit Plain Text override, or it would snap back. Saving re-resolves every open document's `DocumentEntry.environment_key` (new `DocumentRegistry.set_environment_key`).
5. **"Plain text within the environment" is a per-view mode, plus the automatic failure state.** **Plain Text Mode** (offered by every environment except Plain Text) renders the view as Plain Text and disables every environment command and host feature, while the document keeps its environment identity — the menu still names it ("JSON (Plain Text)") and one click turns it back on. It is per view, like the other BF-075 view settings, and is saved with the view in the session (`ViewRecord.extra["environment_plain_mode"]`, alongside the per-view Syntax Profile choice). It wins over the per-view Syntax Profile override, which is restored when the mode is turned off. A failed activation (`FileEnvironmentManager.active_for(...).failed`) lands in the same state automatically, with the menu saying "<Environment> failed to load — showing Plain Text".
6. **Per-document live environments are cached weakly.** `FileEnvironmentManager.active_for(document, key)` keeps one activated instance per `Document` in a `WeakKeyDictionary` (closed documents drop out without attach/detach wiring), re-activating when the key changes. `activate_for` stays stateless as ADR-0013 left it.
7. **Findings get their first UI consumer.** Validate commands open a non-modal findings list (`ui/environment_findings_dialog.py`); activating a row moves the caret to the finding. A validate command distinguishes "skipped — file too large" from "no problems", which `validate()` alone could not.

8. **A document can be pinned to an environment other than its extension's.** The environment menu's **Environment for This Document** picker (an exclusive choice, so a submenu like Whitespace/Tab Width) offers "By Extension (<its environment>)" plus every environment. The pin lives on `DocumentEntry.environment_override` (`DocumentRegistry.set_environment_override`; a per-window weak map for windows with no service), survives extension reassignment, and is saved in the session's `DocumentRecord.extra["environment_override"]`. On restore it is applied right after the document is adopted and before its views open; an unknown key from a newer build is ignored. A document's environment is now computed from pin, else the current extension mapping, every time, and synced onto `DocumentEntry.environment_key`. This also fixes restored documents ignoring the user's extension overrides: the registry's adopt-time default reads extensions only.
9. **Cross-environment command slots are registered, rebindable commands.** A new **Environment** command category holds `environment.format` (Ctrl+Alt+Shift+F; Ctrl+Alt+F is the macOS standard Replace), `environment.minify` (unbound), `environment.validate` (Ctrl+Alt+V), `environment.go_to` (Ctrl+Alt+G), `environment.preview` (Ctrl+Alt+P) and `environment.plain_mode` (Ctrl+Alt+T). Each slot runs the active environment's command of the same local id. It is disabled where that environment has none, shows that environment's label in the menu ("Validate USFM", "Check Brackets"), and is attached to the window so its shortcut works whether or not the slot is in the current menu. All slots appear in, and can be rebound from, the Hotkeys popup.

## Consequences

- The per-view **View > Syntax Profile** override is unchanged but is now purely presentational: environment features follow the document's environment, not the rendered profile (e.g. forcing Markdown rendering on a `.txt` no longer enables Markdown Preview).
- Save As to a different extension now re-renders and re-menus the view from its new environment.
- Still not done: the E6 follow-ups (project `.sty` loading, marker inspector, E7 rich views). Split clones of a view don't copy its Plain Text Mode, the same as the other per-view settings.
